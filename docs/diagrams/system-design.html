Curated Stylist: system design

An AI shopping assistant for 23 independent Indian fashion brands. One Claude agent uses tools to search a real product index and real brand policies, so it never makes up products. The top half is what happens when a shopper asks a question. The bottom half is the background work that prepares the data.

Frontend (browser) Backend (Vercel REST API) Agent + tools LLM (Anthropic Claude) Search (Algolia) Brand stores (Shopify) Storage (GitHub JSON)

One question, step by step

  1. The shopper types in the Stylist drawer. The browser sends POST /api/stylist with the last 6 turns and their wishlist.
  2. The API checks limits and starts the agent loop.
  3. Claude Sonnet 5.5 gets the system prompt (role, rules, when to ask or decline, brand list), the chat and the tool list, then decides which tools to call. The system prompt is cached, so repeat calls read it at about a tenth of the price.
  4. Tools query Algolia (products) and policies.json (returns, shipping), and return real data.
  5. Claude calls respond with its answer and product ids.
  6. The API removes any id no tool returned, then sends the answer and product cards back.
  7. The trace (steps, tokens, ₹, time) is saved after the reply.

Design choices worth saying out loud

  • One agent with tools, not a fixed pipeline: it can combine search and policies in one answer ("silk sarees I can return").
  • No invented products. The agent may only show ids a tool returned, and code enforces it.
  • Hard limits are filters (price, size, gender, returnable), not hopes in a prompt.
  • Rules live in the system prompt, limits live in code. The prompt says how to behave; code enforces what must never break (filters, invented ids, rate limits).
  • Cheap model offline, strong model live. Haiku reads policies once; Sonnet talks to shoppers.
  • Measured, not guessed. Every answer is traced, and evals compare the agent against a no-AI baseline.
